# Tank Arena — 像素街机前端风格实施提示词

请为 **Tank Arena** 实现与 **pixel（像素街机）** 美术素材匹配的前端视觉风格。前端技术栈为原生 ESM、HTML、CSS 与 Canvas 2D；只修改 `client/index.html`、`client/main.js`、`client/render.js`、`client/styles/main.css`，以及需要新增的 `assets/pixel/` 素材文件。不得改变 `server/`、`shared/`、游戏规则、网络协议或服务端权威模型。

## 风格锚点

- 关键词：16-bit 街机、午夜蓝紫机柜、硬像素、有限调色板、清晰的战斗读图、高对比度 HUD。
- 画面使用正交网格、1px/2px 阶梯边缘、短而硬的投影；保持 `image-rendering: pixelated`。不要使用圆角、玻璃拟态、柔焦、渐变光晕、抗锯齿、写实材质或 3D 渲染。
- 高光为奶油白，阴影为深紫；坦克红、蓝、青绿、黄必须在战场上明确区分。禁止人物、真实照片、文字图片、Logo 与水印。

## 素材与主题映射

- 主题值为 `pixel`，素材目录为 `/assets/pixel/`；主题选择由 `body[data-theme='pixel']` 控制，并由 `localStorage` 的 `tank:theme` 持久化。
- 坦克：`tank-red.png`、`tank-blue.png`、`tank-green.png`、`tank-yellow.png`，均为 64×64 透明 PNG，对应 `TANK_COLOR_MAP` 的四种玩家颜色。
- 战场：`tile-ground.png`、`tile-border-steel.png`、`tile-brick-3.png`、`tile-steel.png`，均为 32×32；不得在地面贴图中烘焙地图格线。
- 战斗与 HUD：`bullet.png`（16×16）、`ui-hp-pip-full.png` 与 `ui-hp-pip-empty.png`（14×10）。
- 特效：`fx-hit.png`、`fx-wall-spark.png`、`fx-explosion.png`、`fx-brick-debris.png`、`fx-ram.png`，均为 256×64 的横向四帧表；每帧为 64×64，按从左到右播放，视觉中心与锚点一致。
- `client/render.js` 的 `ASSET_THEMES` 已包含 `pixel`，图片按 `/assets/${theme}/${file}` 预加载。资源不存在、加载失败或主题不在该集合中时，必须继续使用既有 Canvas 几何绘制回退，不得阻塞对局。

## 设计令牌

使用并维持以下像素主题令牌：

```css
--ink: #110f2b;
--panel: #211d4a;
--panel-2: #302a68;
--line: #6658ba;
--line-bright: #b9a6ff;
--paper: #fff4c7;
--muted: #b5aed8;
--acid: #67f5d0;
--signal: #ffda59;
--danger: #ff5a91;
```

- 标题使用粗重无衬线系统字体，短字距、全大写或视觉上等效的街机层级；正文使用清晰的系统无衬线字体；数字使用等宽字体；快捷键使用等宽、奶油白文字与深紫底框。
- 正文使用 `--paper`，辅助文字不低于 `--muted`；危险、禁用、胜负状态不应只靠颜色表达，需有文字或边框/图标差异。浅色主题不可复用本主题的弱文本配色。
- 禁止把 UI 关键文字烘焙进位图。昵称、倒计时、房间号、血量数量与战报均由 HTML 或 Canvas 文字绘制，以保证清晰和本地化。

## 布局与组件

- 保留现有页面结构：顶部栏（品牌、主题选择、连接状态）、大厅、房间、战场 HUD、战报、断连遮罩与结算面板。不得重排或删除现有可访问性标签。
- 顶部栏、视图容器、面板和 HUD 使用直角边框、双线或像素阶梯装饰及 `4px/6px` 硬阴影；避免圆角。桌面以紧凑街机机柜感为主，移动端保持触控区域与文本可读性。
- 按钮默认用深紫底、亮紫边框与奶油白文字；主操作用 `--acid` 或 `--signal`；悬停采用 1–2px 位移或边框提亮；焦点必须有显著 `2px` 外描边；按下压缩硬阴影；禁用态降低对比但仍可辨识且不可仅靠透明度。
- 输入框和四格房间号使用等宽数字、直角边框、深色底；当前格有 `--acid` 焦点框。HUD 的血量优先绘制对应像素能量格；战报保持正文与时间戳层级清楚。
- 淘汰玩家应有低饱和状态、明确“淘汰”文字/图标与不透明度变化；不得把死亡坦克和可操作坦克混淆。

## 动效与减少动态偏好

- 命中、钢墙火花、爆炸、砖墙碎片与相撞冲击仅由对应精灵表驱动；用 `frame = floor(progress * 4)` 切取 `sourceX = frame * 64`，每帧以 64×64 中心锚点绘制。倒计时、GO、玩家昵称和其他文字继续由 Canvas/HTML 绘制。
- 交互动效使用 `steps()` 或短促离散过渡；常规按钮动效不超过 180ms，特效按当前渲染器生命周期播放一次后移除。不要添加持续闪烁或大面积移动背景。
- 在 `@media (prefers-reduced-motion: reduce)` 下关闭非必要的闪烁、扫光和位移动画；保留状态变化、焦点提示和静态结果，特效可直接显示首帧或末帧。

## 验收

- 选择 `pixel` 后，文本、数字、快捷键、连接状态、HUD 与战报在实际背景上均清晰可读；焦点、禁用、危险和淘汰状态可区分。
- 所有素材路径正确；坦克为 64×64、图块为 32×32、子弹为 16×16、HP 格为 14×10；全部特效按横向四帧 64×64 正确切片并中心对齐。
- 任意一张图片加载失败时仍能使用现有 Canvas 几何绘制完成对局；不得引入外部依赖或修改服务端逻辑。
- 在桌面和窄屏下验证大厅、房间、战场、断连遮罩与结算面板；并分别检查 `industrial`、`pixel`、`cartoon`、`neon` 四个主题下正文、辅助文字与快捷键的可读性。
