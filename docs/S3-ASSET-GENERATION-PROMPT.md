# Tank Arena：S3 视觉素材生成提示词示例

将下面整段提示词交给 `game-asset-forge` 使用。它以当前项目的网格、配色、Canvas 渲染与加载回退约束为输入，产出完整的首批素材包。

```text
请使用 game-asset-forge 为 Tank Arena 制作一套可直接接入的 2D 位图视觉素材包。先输出“素材简报”和“资产清单”，确认清单后再按优先级生成；不要修改 server/ 或 shared/ 的游戏逻辑。

【游戏与风格】
- 游戏：俯视角、多人坦克对战、32px 网格地图；画面需要在快速移动和小尺寸下清楚分辨敌我、可破坏物与不可破坏物。
- 风格：克制的工业军械仪表盘风，硬边轮廓、轻微做旧金属纹理、简洁几何体；不是写实照片、不是像素风、不是卡通玩具。
- 视角：严格正俯视（top-down），不使用透视倾斜，不产生侧面或等距视角。
- 光源：右上方偏冷的柔和高光；阴影短而克制。
- 统一底色语境：深橄榄黑地面 #12150f，网格线 #1a1e16。
- 角色强调色：红 #e94f37、蓝 #3f88c5、青绿 #44bba4、黄 #f6ae2d。共同中性色为暖灰、钢灰、砖褐。
- 禁止：文字、数字、Logo、水印、人物、真实战场背景、浓烟遮挡、厚重环境光、边缘裁切、透明素材的纯色底。

【输出与命名】
- 输出目录：client/assets/；PNG，全部带 Alpha 透明通道；小写 kebab-case。
- 单文件不超过 50 KB；适合 nearest-neighbor 缩放，不要在边缘产生模糊半透明白边。
- 每个精灵在画布内保留至少 3px 安全边距；不能裁掉炮管、履带、火花或爆炸边缘。
- 交付 asset-manifest.md，逐项记录：文件、用途、像素尺寸、Alpha、渲染器映射、提示词摘要、验收结果。
- 生成后检查尺寸、透明度、文件大小、命名、实际显示倍率下的可辨识性；若不符合，迭代后再交付。

【资产清单】
1. 玩家坦克：
   - tank-red.png、tank-blue.png、tank-green.png、tank-yellow.png
   - 每张 64×64，透明 PNG。严格正俯视，车体居中；方形履带、中央炮塔、短炮管，车头方向清楚。炮管与履带的视觉边界要在 26px 碰撞盒附近保持清晰，避免显得臃肿。
   - 四张除主色外，造型、光源、阴影和细节完全一致；不在精灵里绘制昵称、血条或选中框。

2. 子弹：
   - bullet.png，16×16，透明 PNG。
   - 小型明亮能量弹芯，暖白 #ffe9b0 为主，外圈可微弱承接发射者颜色；轮廓干净、中心明确，在深色地面上清楚可见。

3. 地面与地图网格：
   - tile-ground.png，32×32，透明 PNG；仅包含极弱的深橄榄工业地面纹理，能够无缝四边拼接，保留足够暗的对比度供网格线单独叠加。
   - 不要将网格线烘焙进地面贴图；渲染器会单独绘制 32px 网格线。

4. 障碍物（均为 32×32，透明 PNG，严格对应一个格子）：
   - tile-border-steel.png：地图外圈用的厚重不可破坏钢制边界；双层边框、斜向金属压纹，视觉最厚重。
   - tile-brick-3.png：满耐久可破坏砖墙；砖褐 #8a5a3c，清晰横向砖缝。
   - tile-brick-2.png：剩余 2 点耐久的砖墙；沿用上一张构图，新增一条清晰裂纹，不要完全碎裂。
   - tile-brick-1.png：剩余 1 点耐久的砖墙；沿用同一构图，新增第二条明显裂纹，仍保留主要墙体。
   - tile-steel.png：内部不可破坏钢块；钢灰 #4a5560、铆钉与小型中心高光，不能与边界钢墙或砖墙混淆。
   - 每种图块必须能无缝接邻格；砖墙三种耐久状态必须一眼可分。

5. 血量与战斗标记：
   - ui-hp-pip-full.png、ui-hp-pip-empty.png，各 14×10，透明 PNG。
   - 满血格使用青绿 #44bba4，低血时可由渲染器换成红 #e94f37；空血格用低对比深灰边框。不要画心形、数字或文字，形状应与工业仪表条一致。
   - ui-self-ring.png，32×32，透明 PNG：一像素感的白色矩形选中框，用于本机坦克周围；中部完全透明。

6. 命中特效与毁坏特效：
   - fx-hit.png，64×64，4 帧横向精灵表（总画布 256×64），透明 PNG：坦克命中时的暖白核心与橙色环形爆点，由小到大、快速消散。
   - fx-wall-spark.png，64×64，4 帧横向精灵表（总画布 256×64），透明 PNG：命中钢墙时的小火花，不要像坦克爆炸。
   - fx-explosion.png，64×64，4 帧横向精灵表（总画布 256×64），透明 PNG：坦克淘汰时的双层橙色爆炸，外圈更大，中心更亮；每帧中心锚点一致。
   - fx-brick-debris.png，64×64，4 帧横向精灵表（总画布 256×64），透明 PNG：砖墙摧毁时向四周散开的砖褐碎块。
   - fx-ram.png，64×64，4 帧横向精灵表（总画布 256×64），透明 PNG：坦克相撞的橙红交叉冲击线，与子弹命中圆环明显不同。

7. UI 装饰（可选但建议生成）：
   - ui-panel-corner.png，32×32，透明 PNG：军械仪表盘风格的细角标，不含文字，可用于 HUD 面板四角。
   - ui-countdown-frame.png，256×256，透明 PNG：倒计时数字周围的细工业圆环装饰，中央完全留空，不能影响文字可读性。

【接入约束】
- 当前地图为 30×20 格、每格 32px；坦克实际碰撞盒 26px，但美术文件可为 64×64，渲染时以坦克中心对齐。
- 当前客户端会将墙体、坦克、子弹与特效替换为 drawImage；素材加载失败时必须继续使用既有 Canvas 几何图形回退。
- 不要合并为单张大图集；除上述特效精灵表外，每个文件独立交付。
- 先用 tank-red.png、tile-brick-3.png 和 fx-explosion.png 作为风格样本；确认风格一致后再完成其余文件。

【验收输出】
交付时给出：
1. 所有生成文件的列表与尺寸；
2. 每个文件对应的渲染器映射建议；
3. 特效表切片规则（每帧 64×64、从左至右 4 帧）；
4. 无缝图块、透明背景、耐久状态可区分、加载回退不受影响的验收结论；
5. asset-manifest.md。
```

## 接入前核对

- 坦克和特效保留透明边缘，图块尺寸均严格为 32×32。
- `tile-brick-3/2/1` 的破损程度与服务端耐久含义一致：3、2、1。
- 生成工具若不能可靠输出精灵表，可分别生成 4 帧，再用固定的 64×64 画布横向合并；合并后仍需检查锚点一致。
- 接入只修改 [client/render.js](../client/render.js)，并保留现有几何绘制作为资源加载失败时的回退。
