AI 坦克竞技场：在线多人对战游戏与可复用 Skill
参与形式：3～4 人组队；建议用时：约 7 小时；目标学员：已完成 AI 工具入门学习的校招生。题目名称	AI 坦克竞技场：在线多人对战游戏与可复用 Skill
业务或工作场景的背景	互动游戏、在线活动和实时协作产品通常需要多角色共同完成，包括产品目标拆解、客户端交互、服务端状态管理、美术内容生产、工程部署和测试验证等。
传统的小型原型开发中，美术和代码往往串行推进，容易遇到以下问题：
● 素材风格不统一。
● 需求频繁变化。
● 多端联调复杂度高。
● 实时状态问题难以复现。
● 从想法到可玩版本的周期较长。
AI 工具可以辅助需求拆解、脚手架搭建、代码生成、素材创作、测试设计和故障分析，但“一次生成”并不等于完成工程交付：
● 生成的素材需要满足尺寸、透明通道和风格约束。
● 生成的代码需要适配现有工程并经过运行验证。
● 实时状态需要通过多个客户端进行联调。
● 有效的方法需要整理成团队可以再次调用的 Skill。
本题以经典坦克大战为载体，模拟一次小型但完整的 AI-Native 研发实践。团队需要在有限时间内完成分工、接入公司工程平台、实现多人游戏闭环、使用 AI 提效，并留下可验证、可复用的工程资产。
 
要解决的核心问题	

请设计并实现一个浏览器可运行的在线多人坦克对战小游戏。不同玩家能够进入同一房间，在同一局游戏中移动、射击、受伤，并得到一致的胜负结果。

团队不仅要交付一个可玩的 Demo，还需要用作品回答并证明以下问题：
1. 如何在 7 小时内利用 AI 完成从需求、素材、编码、联调到部署的工程闭环？
2. 如何划分客户端表现与服务端权威状态，保证不同玩家看到的关键游戏结果一致？
3. 如何把一次性的 AI 对话整理成有输入、步骤、约束和验证方法的可复用 Skill？

本题重视“完整、可运行、可复现”，不鼓励在核心闭环尚未跑通前堆叠复杂玩法。


任务范围与核心玩法	必做 1：房间与玩家
● 支持创建或加入房间。
● 输入相同房间号的 2～4 名玩家可以进入同一局。
● 能够区分不同玩家。
● 能够正确处理玩家主动离开或连接断开的情况。
必做 2：基础战斗
● 玩家可以控制坦克移动和射击。
● 存在地图边界和至少 1 类障碍物。
● 实现子弹与坦克的碰撞判定。
● 至少包含生命值或有限复活次数。
● 具备明确、可验证的对局结束规则。
必做 3：状态同步
● 房间、玩家、坦克、子弹、生命值和胜负结果等关键状态，由服务端统一维护或裁决。
● 同一房间内的客户端能够持续看到其他玩家的移动、射击、受伤和对局结果。
● 新加入或重新进入房间的客户端能够获得当前对局状态。
● 不要求实现复杂的断线续玩。
推荐采用服务端权威模型：客户端发送操作意图，服务端更新世界状态并广播结果。
必做 4：美术与反馈
至少提供以下四类可辨识的视觉资产或效果：
1. 坦克。
2. 地图或障碍物。
3. 子弹。
4. 命中或爆炸反馈。

预期所有视觉资产需要使用 AIGC 工具辅助生成或迭代，不建议纯手工制作。

必做 5：工程运行
● 项目接入比赛指定的公司工程搭建平台。
● 能够在规定环境中完成项目创建、构建和发布或预览。
● 提供一条明确的本地启动命令。
● 提供一条明确的构建或测试命令。
必做 6：Skill 沉淀
至少交付 2 个可复用 Skill：
1. 至少 1 个面向美术资产生产。
2. 另 1 个可从代码生成、多人状态同步、自动化测试、日志排障或工程部署中选择。
每个 Skill 均应包含：适用场景、输入和输出、操作步骤、使用约束、验证方法、至少一个使用示例。
只提交一段 Prompt，不视为合格 Skill。

预期要求	
要求	解释
可玩性	两名玩家可在同一房间完成一局有明确结果的对战，操作和战斗反馈清楚。


多人一致性	关键战斗状态由服务端裁决；在正常网络环境下，两个客户端最终显示的生命值、淘汰和胜负结果一致。


基础鲁棒性	无效输入、玩家断开、资源加载失败或服务端异常中至少处理 2 类，并给出日志或用户提示。


 工程完整性	可按 README 从干净环境启动；工程结构清晰，关键参数不散落在多处，禁止把密钥写入仓库。


AI 使用可追踪	说明 AI 在分析、素材、实现、调试和验证中实际参与了哪些步骤，以及团队对生成结果做了哪些人工判断。


Skill 可复用	每个 Skill 均应包含适用场景、输入、输出、操作步骤、约束、验证方法和至少一个使用示例；只提交一段 Prompt 不视为合格 Skill。

验收与评审	基础验收门槛
以下各项全部满足，作品方可进入完整评分：
● 评审可以依据 README 启动项目，或访问团队提交的有效预览地址。
● 至少两个独立客户端可以加入同一房间并完成一局对战。
● 移动、射击、碰撞、生命值或复活和胜负闭环均可现场验证。
● 两个客户端最终展示一致的关键战斗结果。
● 提交至少 2 个符合格式要求的 Skill，其中至少 1 个面向美术资产生产。
